## 0. 一页摘要

| 项 | 内容 |
|---|---|
| **目标** | 提升 PACS 跨域分类准确率，针对已确诊的**预测塌缩**问题 |
| **诊断结论** | 模型在域偏移下**塌缩到单一类别**（sketch→giraffe 占 71%，cartoon→guitar 占 89%），不是"图片太难" |
| **分工形式** | **三个人，三个独立模块**，每人可独立跑完实验出结论，**零交接** |
| **是否需串行** | **否。三者完全并行**，唯一硬前提是 epoch 协议修复（§1.5、§5.1） |

| **共同前提** | **epoch 协议修复必须先做完**（见 §5），否则三份结论都不可信 |

## 1. 诊断依据（三人共享的出发点）

以下数据来自 `member4_training_eval/confusion.py` 与 `show_per_class.py`，三个不同 checkpoint、三个域上完全一致。

### 1.1 预测塌缩

```
sketch_test   → 71% 的图像被预测为 giraffe
   dog      → giraffe 81%,  guitar 15%
   elephant → giraffe 83%
   horse     → giraffe 87%
   person    → giraffe 92%

cartoon_test  → 89% 的图像被预测为 guitar
   dog      → guitar 89%
   elephant → guitar 88%
   horse     → guitar 77%
   person    → guitar 94%
```

### 1.2 逐类准确率（`adain_a1p0_b0p7`）

| 类 | photo | art | cartoon | sketch | 跨域均值 |
|---|---|---|---|---|---|
| guitar | 100.0% | 94.1% | 100.0% | 99.0% | **97.7%** |
| house | 100.0% | 89.9% | 83.7% | 84.2% | 85.9% |
| elephant | 100.0% | 77.9% | 33.2% | 77.1% | 62.7% |
| horse | 100.0% | 82.4% | 41.7% | 61.2% | 61.7% |
| giraffe | 100.0% | 71.7% | 49.1% | 42.9% | 54.6% |
| dog | 90.6% | 83.2% | 24.3% | 4.2% | 37.2% |
| **person** | 100.0% | 18.7% | 6.6% | **0.1%** | **8.5%** |

### 1.3 三条关键结论

**① 塌缩目标不是最大类。** 训练集里 `house` 占 25.9%（最大），但没有任何域塌缩到 house。塌缩到的是 `guitar`（11.9%）和 `giraffe`（11.1%）——训练集里**最小**的两个类。
→ **否证了类别不平衡解释。**

**② 塌缩目标是剪影最可分的类。** giraffe 的长颈、guitar 的琴身，是 PACS 七类里轮廓最独特的。
→ 模型在域偏移下**退化成了"只看剪影"**。

**③ "主体占幅大导致识别不了"被数据否掉。** 主体占幅越大的图像反而越容易答对（最难辨认的 1/5，准确率反而高 13–15 点）。真正相关的是"主体从背景的凸显度"（最难辨认的 1/5，准确率低 13–22 点）。

### 1.4 这三个模块各自针对哪一条

| 模块 | 针对 | 机制假设 |
|---|---|---|
| **A. 类别平衡与采样** | 结论 ① | 塌缩源于训练信号中 `person`/`dog` 这类高噪声类占比过高，稀释了可分剪影的学习 |
| **B. 决策边界平滑化** | 塌缩本身 | 塌缩是过度自信的单类吸引子，用 mixup / logit 平滑直接压制 |
| **C. 剪影强化增强** | 结论 ② | 模型已在依赖剪影，那就**主动强化并多样化**剪影，而不是被动依赖 |

### 1.5 三者并行，不需要等彼此

**B 和 C 都不依赖 A 的结果，A 也不依赖 B 和 C。** 三个模块作用在不同层面，
改的是不同的文件，因此可以完全并行开工、各自跑完、各自出结论。

| | 改什么 | 改哪个文件 | 依赖谁 |
|---|---|---|---|
| **A** | 采样权重 | `data.py` | 只依赖 Photo Val + 训练集自身 |
| **B** | 训练时的输入/标签 | `train.py` | **不依赖任何人** |
| **C** | α 图的形状与强度 | `member3_structure_preserving/` | **不依赖任何人** |

**A 改 `data.py`、B 改 `train.py`**，这两个文件是分开的，天然不冲突。

唯一存在的是**解读层面**的依赖，不是**执行层面**的：

- 如果 A 成功了，B 和 C 的结论在最后合写时会多一层背景（mixup 的收益
  是在"均衡采样"之上还是独立）
- 但这不影响"谁先跑完谁先出结论"

**唯一的硬前提是 epoch 协议修复**（§5.1），那是所有人共同的对照基线，
不是模块之间的依赖。

依赖图：

```
        成员 4：epoch 修复（阻塞项，所有人等这个）
                          │
        ┌─────────────────┼─────────────────┐
        ↓                 ↓                 ↓
      模块 A            模块 B            模块 C
     （采样）          （mixup）        （轮廓带）
        │                 │                 │
        └─────────────────┼─────────────────┘
                          ↓
              最后合并（成员 4）
              各自独立汇报，不混进主表
```

## 2. 模块 A：类别平衡与自适应采样

**负责人：（待认领）** · 代码位置：`repo/member4_training_eval/`

### 2.1 要解决的机制

训练集 1,349 张，7 类分布为 house 25.9% / horse 16.8% / dog 12.1% / guitar 11.9% / person 11.3% / giraffe 11.1% / elephant 10.9%。

`person` 与 `dog` 合计占 23.4%，但这两类恰恰是**剪影最不稳定**的（person 姿态衣着多变，dog 与 horse 轮廓相近）。它们贡献了大量**梯度上互相打架**的样本——同一张 person 图可能是侧脸也可能是背影，模型学到的不是一个稳定的类别原型，而是"person 这个概念有几百种样子"。

结果就是：模型无法为 person 建立任何稳定表征，于是 person 的梯度噪声主导了最后的决策边界，把所有模糊输入吸走。

**模块 A 的假设**：降低高噪声类的样本权重，能让可分剪影类（guitar/house/elephant/horse）的原型更干净，从而**减少塌缩的吸引子数量**。

### 2.2 三档实验（独立跑完，不依赖别人）

| 档 | 名称 | 做法 | 预期 |
|---|---|---|---|
| A1 | **类别均衡采样** | 按类做 `WeightedRandomSampler`，把每类采样概率拉平到 1/7 | 最保守的对照 |
| A2 | **按域稳健性加权** | 用 Photo Val 上的各类准确率（或逐类 margin）作为权重：跨域表现差的类降权 | 直接对准"哪些类在制造噪声" |
| A3 | **样本质量加权** | 用已有的 objectness map 给训练图打质量分（主体凸显度），低质量样本降权 | 针对 §1.3 ③ 的真实因素 |

**A1 是必做的基线**，A2/A3 是在 A1 之上的变体。

### 2.3 关键设计约束

- **只改采样，不改数据。** 三个档位共用同一份 1,349 张训练图，不生成任何新图 → **零生成成本**
- **不许用目标域信息。** A2 的权重必须来自 **Photo Val**，不能来自 Art/Cartoon/Sketch 的准确率（否则违反纪律 2）
- **不许删样本。** 降权 ≠ 剔除。剔除会让"训练集更干净"和"训练集更小"混淆（`duplicate` 对照已经证明这个混淆有多致命）

### 2.4 实现方式

在 `data.py` 增加一个可选的采样器：

```python
def load_train_dataset(group, aug_manifest=None, sampler=None):
    ...
```

`train.py` 增加一个 `--sampler` 参数（默认 `none`，保持现有行为不变）。

### 2.5 交付物

- `member4_training_eval/class_sampling.py`：三种权重的计算逻辑，全部只读 Photo Val 与训练集本身
- `member4_training_eval/plot_sampling_weights.py`：权重分布图（一张图，三档对照）
- 三档 × 5 种子的训练结果
- `member4_training_eval/summarize_sampling.py`：三档之间的配对检验
- 一段结论：**「采样策略能把跨域准确率抬高多少点，以及塌缩是否减轻」**（用混淆矩阵的前预测占比作为塌缩程度的量化指标）

### 2.6 验收标准

- [ ] 不生成任何新图片，`train_images` 仍为 1,349（或增强组的 2,698）
- [ ] 权重只来自 Photo Val 或训练集自身，不接触目标域
- [ ] 三档各自独立出结论，A1 是另外两档的对照
- [ ] 报告塌缩指标：**最大预测类别占比**（sketch 域从 71% 降到多少）
- [ ] 5 种子，配对 t 检验

### 2.7 成本

| 项 | 成本 |
|---|---|
| 生成 | **0**（不生成数据） |
| 训练 | 3 档 × 5 种子 = 15 次 × 210s ≈ **0.9 h** |
| 代码 | 约 2 h |

## 3. 模块 B：决策边界平滑化（压制塌缩）

**负责人：（待认领）** · 代码位置：`repo/member4_training_eval/model.py` + `train.py`

### 3.1 要解决的机制

塌缩是**过度自信的单类吸引子**：模型对一个类别的 logit 变得极大，任何模糊输入都被吸过去。这在训练里的表现是：

- `person` 类在 sketch 域 0.1% 准确率，但**所有**错误预测集中到 giraffe/guitar 两个类
- 71% 的 sketch 图像共享同一个预测

这不是"分不清"，是"没有别的选择"。ResNet-18 在 660 步的紧预算下收敛到一个**尖锐的**解。

**模块 B 的假设**：塌缩是优化过程的问题，不是数据的问题。给决策边界加平滑（mixup / logit 平滑 / 更大的 label smoothing），模型就会被迫在多个类之间分配概率质量，塌缩自然缓解。

### 3.2 四档实验（独立跑完）

| 档 | 名称 | 做法 | 说明 |
|---|---|---|---|
| B1 | **mixup** | 样本内线性插值，标签按 λ 插值；λ ~ Beta(α,α)，默认 α=1.0 | 最标准，文献最多 |
| B2 | **CutMix** | 把一张图的矩形块贴到另一张图上，标签按面积比插值 | mixup 的空间版本，对"主体占幅"问题天然敏感 |
| B3 | **logit 平滑 / 温度** | 训练时对 logit 做温度缩放或加噪声，抑制尖锐 logit | 最轻量，直接针对"过度自信" |
| B4 | **label smoothing 强化** | 当前 0.1 → 试 0.2 / 0.3 | 零代码成本，先跑 |

**B4 必须先跑**（改一个常数即可），B1/B2 是主力，B3 是备选。

### 3.3 关键设计约束

- **架构改动 = 新的 config_hash。** 纪律 8 明确：模型结构变更属于例外，必须独立成组、独立汇报，**不得与 `ecc6090e5b29` 的结果混在同一张表直接比较**
- **B1/B2 改的是训练过程，不是架构**（权重名称不变），可以复用现有的 MixStyle 那套 `_StageWithMixStyle` 式的"参数名不变"做法
- **推理期必须完全等价。** mixup/CutMix 只在训练期生效，推理时是恒等映射——这样报告的准确率就是普通网络的准确率
- **B4 改 label smoothing 会改 config_hash**（它在 `training_config()` 里），所以 B4 也必须独立成组

### 3.4 与模块 A 的关系

模块 A 改**采样**，模块 B 改**优化**。两者**正交**：

- 单独跑 A1（均衡采样）+ 单独跑 B1（mixup），各自独立出结论
- **不需要做 A×B 的完整交叉**（那是 3×4=12 组，代价太大）
- 若时间允许，只跑一个组合：`A1 + B1`（最保守 + 最标准），验证两者是否叠加

### 3.5 实现方式

`model.py` 里 mixup/CutMix 应实现为**训练循环里的操作**（不是网络层），因为它作用于输入和标签，不作用于特征：

```python
# train.py 中，在 forward 之前
if mixup_alpha > 0:
    images, labels_a, labels_b, lam = mixup_batch(images, labels, mixup_alpha)
    loss = lam * criterion(output, labels_a) + (1 - lam) * criterion(output, labels_b)
```

CutMix 同理，但要在标签插值时用面积比而非 λ。

### 3.6 交付物

- `member4_training_eval/augment_batch.py`：mixup / CutMix 的实现（纯函数，可单测）
- `member4_training_eval/plot_mixup_examples.py`：混合后的图像样例图（人眼要能确认混合正确）
- 四档 × 5 种子的训练结果
- `member4_training_eval/summarize_mixup.py`：配对检验 + **塌缩指标对比图**
- 一段结论：**「决策边界平滑化能否把塌缩从 71% 降下来，以及跨域准确率是否跟着涨」**

### 3.7 验收标准

- [ ] 推理期 forward 与原模型**逐位等价**（写一个断言测试）
- [ ] 混合后的图像人工可辨认（看样例图）
- [ ] 每档独立成组，有自己的 config_hash
- [ ] 报告**塌缩指标**：sketch 域最大预测类别占比
- [ ] 5 种子，配对 t 检验

### 3.8 成本

| 项 | 成本 |
|---|---|
| 生成 | **0** |
| 训练 | 4 档 × 5 种子 = 20 次 × 210s ≈ **1.2 h** |
| 代码 | 约 2 h |

## 4. 模块 C：剪影强化增强（换载体）

**负责人：（待认领）** · 代码位置：`repo/member3_structure_preserving/`

### 4.1 要解决的机制

§1.3 结论 ②：**模型在域偏移下已经退化成"只看剪影"**。

这其实是好消息——它说明剪影是 PACS 上真正有判别力的信息。我们之前做的"结构保持"失败，是因为**载体错了**：

| 之前的尝试 | 为什么失败 |
|---|---|
| Sobel 空间调制 | 地图代表纹理而非物体，符号翻转（EdgeScore −0.0031） |
| `center` 中心先验 | 强度压到 0.3068，"少样式化"主导了增益，下游 −3.48 点 |
| **线稿单独训练** | 丢掉纹理/颜色/现实感，整体 ≤ `original`（40.83%） |
| **软投票线稿** | 机制有效（+1.73 点 vs 匹配对照），但载体仍是线稿，仍打平 |

**线稿的根本问题是它替换了图像**，而模型需要的不只是剪影——它需要剪影**加上**纹理线索。

**模块 C 的假设**：既然模型已经依赖剪影，那就**主动提供更多样的剪影**，同时**保留原图的纹理**。

### 4.2 三档实验（独立跑完）

| 档 | 名称 | 做法 | 关键区别 |
|---|---|---|---|
| C1 | **窄轮廓带保护 α 图** | α₀=1.0 强样式，但**只在窄轮廓带**上保留内容特征 | 改的是**地图的形状**，不是所在层 |
| C2 | **多尺度剪影增强** | 生成增强图时，除了主体，还增强**部件轮廓**（琴颈、屋脊、象鼻） | 针对细长结构 |
| C3 | **剪影多样化增强** | 同一张原图生成**多个**不同风格/不同视角增强样本（而不是 1 个） | 直接扩大剪影多样性 |

**C1 是主力**，因为它最直接对应"换载体"这个判断，且**零生成成本**。

### 4.3 C1 的具体做法（这是本模块的核心）

> **修正说明（2026-11-26，复核代码后）**
>
> 本文初稿写"C1 是特征层改法，而现有的 `ours` 是像素层改法"。**这个前提是错的**，现予修正。
>
> 核查 `member3_structure_preserving/stylizer.py:114-120` 与 `member2_adain/adain.py:249-253` 后确认：**现有的空间调制本来就在特征层**，且 `adain.mix()` 本来就接受空间 alpha 图：
>
> ```python
> # stylizer.py
> feature_alpha = F.interpolate(alpha_map, size=content.features.shape[-2:], mode="area")
> mixed = self.model.mix(content.features, style_features, feature_alpha)
>
> # adain.py
> def mix(self, content_feat, style_feat, alpha=1.0):
>     """AdaIN, then blend with alpha. alpha is a scalar or a spatial map."""
>     stylized = adaptive_instance_normalization(content_feat, style_feat)
>     alpha_map = _alpha_tensor(alpha, stylized)
>     return alpha_map * stylized + (1.0 - alpha_map) * content_feat
> ```
>
> **所以"C1 要换载体"的准确含义不是换层，而是换保护对象的形状**——从"大面积区域"换成"窄带"。
> 这对模块 C 是好消息：基础设施全部现成，实现难度低于初稿估计。

**当前实现（`ours` 组，α₀=0.5，beta=0.7）**：

```
alpha_map(x,y) = alpha_0 * (1 - beta * M(x,y))     # M = Sobel 纹理响应
F = alpha_map * AdaIN(Fc, Fs) + (1 - alpha_map) * Fc
```

问题不在"在哪一层"，而在**地图 M 的形状**和**α₀ 太小**。

**C1（新）**：

```
# alpha_0 = 1.0（强样式，已验证的最优区间：adain_a1p0_b0p7 = 45.22%）
# 但只在**窄轮廓带**上保留内容特征
band = dilate(silhouette) - erode(silhouette)        # 轮廓带，几个像素宽
w = alpha_0 * (1 - gamma * band_normalized)          # gamma 小
F = w * AdaIN(Fc, Fs) + (1 - w) * Fc
```

**与两个已有空间调制组的三个本质区别**：

| | `ours`（Sobel） | `ours_fg_center` | **C1（新）** |
|---|---|---|---|
| 调制所在层 | 特征层 | 特征层 | 特征层（**相同**） |
| 地图 M 的形状 | 纹理响应（弥散） | 高斯中心（大面积） | **窄轮廓带** |
| α₀ | 0.5 | 0.5 | **1.0** |
| 保护范围 | 纹理密集处 | 中心 34% 区域 | **只有轮廓的几个像素** |
| mean α | 0.3736 | 0.3068 | **≈0.95+（几乎不损失强度）** |

**为什么窄轮廓带能同时避开两个已有组的失败**：

- `ours_fg_center` 失败，是因为保护了**大面积**区域 → 整体样式强度被压到 0.3068 → 收益被"少样式化"主导。窄带只有几个像素宽，**对 mean α 的影响可以忽略**，这个混杂自然消失。
- `ours` 失败，是因为 Sobel 地图代表**纹理**而非物体 → 符号翻转（EdgeScore −0.0031）。轮廓带来自 **label-free 的 objectness 剪影**，代表物体本身，符号正确。

**C1 实际要新增的代码（比初稿少得多）**：

1. 轮廓带算子（从 `attention_map.py` 的 objectness map 取剪影 → 形态学梯度 → 归一化）
2. `spatial_alpha` 的一个新分支，或一个新的 modulation kind（如 `silhouette_band`）
3. **不需要**重写特征层调制逻辑（现成）

### 4.4 关键设计约束

- **必须报告总有效 α。** C1 改了调制方式，mean α 必然与对照组略有不同 → 必须报告，并在超限时作废重跑（见 §4.6）
- **对照组与实验组必须成对。** C1 的对照是"同样 α_0=1.0 但无轮廓带保护"，而不是 `adain_matched`（那个是 α=0.374 的）
- **C1 应该与 `adain_a1p0_b0p7` 直接比较**。那个组正是均匀 α_0=1.0 的增强集，与 C1 同强度，差的就是轮廓带本身。窄带只让 mean α 略降，所以不需要再为 C1 单独造一个 matched 对照
- **轮廓带宽度 γ 要预先固定**，不能按目标域结果调（纪律 1）
- **不许用真标签。** 剪影图必须来自 label-free 的 objectness map（`attention_map.py` 已有）

### 4.5 交付物

- `member3_structure_preserving/silhouette_protect.py`：轮廓带提取（剪影 → 形态学梯度 → 归一化），并接到 `spatial_alpha` 的新分支上
- `member3_structure_preserving/generate.py` 的一个 `--modulation silhouette_band` 模式（与现有 `--modulation foreground` 同级）
- 三档的增强集生成（如果需要）+ 训练结果
- `member3_structure_preserving/plot_silhouette_bands.py`：轮廓带可视化（要能看清带子落在哪里）
- `member3_structure_preserving/summarize_silhouette.py`：配对检验 + 逐类准确率对比
- 一段结论：**「剪影强化能否把 guitar/house 那类高剪影可分性的优势传递给 person/dog」** ← 这是判定模块 C 成功的**核心指标**

### 4.6 验收标准

- [ ] 有强度匹配的均匀对照
- [ ] 轮廓带可视化，人眼能确认位置正确

## 8. 判定标准：怎么算"成功"

三个模块**各自独立判定**，不互相影响。判定用两个指标：

### 8.1 主指标：跨域平均准确率

与 `original`（修复 epoch 后）做配对 t 检验，5 种子。

- **成功**：p < 0.05 且提升 ≥ 1.5 点
- **部分成功**：提升 0.5–1.5 点
- **失败**：提升 < 0.5 点

### 8.2 机制指标：塌缩占比

`collapse_ratio`（sketch 域最大预测类别占比），现状 **0.71**。

- **机制成立**：塌缩占比显著下降（配对 t 检验）
- **注意**：塌缩下降但准确率不涨 = 症状消失病因还在，这种情况要如实报告

### 8.3 模块 C 的专属指标

**person 类的跨域准确率**（现状 8.5%）。

这是模块 C 的核心判定：剪影强化的意义就在于**把高剪影可分性的优势传递给低剪影可分性的类**。如果 C1 提高了总准确率但 person 纹丝不动，说明它只是加固了本来就会的类，**那就不算解决了我们诊断出的问题**。

## 9. 风险与预案

| 风险 | 预案 |
|---|---|
| **epoch 修复后所有基线数字都变** | 这是预期的。所有人用**同一套修复后的基线**做对照，不要用旧数字 |
| **三人的 config_hash 撞了** | 成员 4 在 `config.py` 注册时用**各自的参数**（sampler 描述 / mixup alpha / γ 值）参与 hash 计算，保证不同 |
| **模块 C 重蹈 `center` 覆辙** | 预先固定 γ，并**强制配强度匹配对照**。若 mean α 差异 > 0.02，该组结果作废重跑 |
| **GPU 冲突** | 三人各占约 1 小时，用 `run_sweep.py` 统一编排，**限制并发为 2**（历史上并发 3 会 OOM） |
| **磁盘** | 每个 checkpoint 43 MB。训练完删 `last.pt`，只留 JSON |
| **A 的权重用了目标域信息** | 严格检查：A2 的权重只能来自 Photo Val。发现即作废 |
| **B 的 mixup 在推理期没关** | 写断言测试，推理期 forward 必须与原模型逐位等价 |
| **三人都失败** | 那就如实报告"三个方向都被否证"，并回到 §1 的诊断重新选方向。**这本身是合格的科研产出** |
