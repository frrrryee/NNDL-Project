## 1. Photo Val 安全门 + 机制指标排序

### 1.1 为什么需要两道判据

**Photo Val 单独无法做选型。** `check_val_discrimination.py` 的测量结果：

- 主表每一组的 Photo Val 落在 **98.13% – 98.93%**
- 总跨度仅 **2.00 个百分点**
- 而**单张验证图 = 0.67 个百分点**，种子间波动 0.30–0.60%

→ **该 split 已饱和**。它能**排除**明显更差的候选，但**无法对接近的候选排序**。

因此采用两道职责分离的判据：

| 判据 | 作用 | 数据来源 | 是否接触目标域 |
|---|---|---|---|
| **判据 1：Photo Val 安全门** | 淘汰明显更差的候选 | 源域 held-out split | **否** |
| **判据 2：机制指标排序** | 在通过门的候选中选出最优 | 仅图像本身，无标签 | **否** |

**两道判据都不使用任何目标域图像**，`target_domain_used: false`。

### 1.2 判据 1 的实现：安全门

实现于 `repo/member4_training_eval/select_foreground_final.py`。

```python
gate = args.gate_tolerance          # 默认 0.01 = 1 个百分点
best_validation = max(validation[k]["mean"] for k in trained)
passed   = [k for k in trained if validation[k]["mean"] >= best_validation - gate]
rejected = [k for k in trained if k not in passed]
```

- 容差 `gate_tolerance = 0.01`（1 个百分点 ≈ 1.5 张验证图）
- 候选：`spectral` / `center` / `spectral_center`
- 每个候选 3 个种子，取 `reported_val_acc`（回退到 `best_val_acc`）

**实测结果：三个候选全部通过门，一个都没被淘汰。**

| 候选 | 均值 | std | n | 每种子 |
|---|---|---|---|---|
| `spectral` | **97.33%** | 1.15% | 3 | 98.00, 98.00, 96.00 |
| `center` | 97.11% | 1.02% | 3 | 98.00, 97.33, 96.00 |
| `spectral_center` | 97.33% | 0.00% | 1 | 97.33 |

→ **安全门在本例中完全没有起到区分作用**（这本身是重要信息：门只能筛掉明显坏的，不能选出好的）。

### 1.3 判据 2 的实现：机制指标排序（含强度调整）

**核心难题**：一个地图如果让**平均样式强度**下降很多，那么风格化后的图更接近原图，**EdgeScore 自然更高**——这是"少样式化"的副产品，**不是机制改进**。

解法是**强度调整（strength-adjusted）**：

```python
difference  = ours_edgescore - matched_control_edgescore   # 配对差
deficit     = max(0.0, NOMINAL_ALPHA - effective_alpha)    # 强度亏损
adjusted    = difference.mean() / deficit                  # 每单位"扣留强度"的增益
```

其中：
- `NOMINAL_ALPHA = 0.5`
- `effective_alpha` **从生成器自己的 `analysis.json` 读取**，不是重算——保证是生成器实际用的数
- 对照组是该候选**自己的**强度匹配均匀对照（`manifest_adain_matched.txt`）
- 统计量：配对 t 检验（`stats.ttest_rel`）、`fraction_worse`（保留更差的图占比）

**实测结果（n=200 张）：**

| 候选 | mean_diff | std | % worse | effective α | deficit | **adjusted** | paired p |
|---|---|---|---|---|---|---|---|
| `spectral` | +0.00097 | 0.0056 | 44.0% | 0.4622 | 0.0378 | +0.0256 | 0.0161 |
| **`center`** | **+0.03361** | 0.0285 | **3.0%** | **0.3068** | **0.1932** | **+0.1740** | 1.04e−39 |
| `spectral_center` | +0.00146 | 0.0059 | 45.0% | 0.4601 | 0.0399 | +0.0366 | 0.00056 |

**选型结果：`selected = "center"`** —— 它在两项上都"最优"：
- 原始增益最大（+0.0336，是其他两个的 **23–34 倍**）
- 强度调整后仍然最大（+0.1740）
- 保留更差的图占比最低（3.0% vs 44–45%）
- 配对 p = 1.04e−39（极显著）

### 1.4 关键失效：机制指标**不能**预示 DG

这是本日最重要的教训。

| 组 | 跨域 avgacc | vs 自身匹配对照 |
|---|---|---|
| `ours_fg_center` | **41.90%** | **−1.26 点, p=0.0224** |
| `ours_fg_center_matched` | 43.17% | （对照本身） |
| `adain_matched` | 45.39% | −3.48 点, p=0.0010 |
| `ours`（Sobel） | 45.22% | — |

**选型机制指标最强的 `center`，在下游显著有害。**

**根因**：EdgeScore 度量的是"边缘保留程度"，它无法区分
- **"保住了结构"**（想要的）
- **"样式化不够"**（不想要的）

`center` 地图把 `effective_alpha` 压到 **0.3068**（Sobel 是 0.3736），即**施加的样式比对照组还少**。它的 EdgeScore 增益**主要来自"少样式化"**，而不是"空间位置选对了"。`strength_adjusted` 除以 deficit **仍然没能剥离这个混淆**——因为 deficit 只惩罚了*均值*，惩罚不了*空间分布*上的差异。

**这直接导致一条已被证伪的工作流**：
> Photo Val 安全门 → 机制指标排序 → 选定地图 → 训练 → 下游验证
>
> 前两步都通过了，第三步得到的却是**显著更差**的结果。

**教训**：**机制指标（EdgeScore 类）只能用于"排除"，不能用于"排序"**。最终选型必须靠下游跨域准确率。

## 2. 软投票：实现细节与最终成果

### 2.1 背景与假设

线稿增强分支的假设是"**形状偏置**（shape bias）能提升 PACS 跨域泛化"。设计要点是**两个信号分工**，而不是投票：

- **色块（SLIC 超像素）**回答"**边界在哪**"
- **注意力语义**回答"**这条边值不值得画 / 值不值得强调**"

软投票是在此基础上，把"强/弱二值切分"换成**连续权重**。

### 2.2 注意力图来源（label-free objectness）

实现于 `repo/member3_structure_preserving/attention_map.py`。

**思路**：用 ImageNet 预训练 ResNet-18（就是分类器本身的骨架）做**无标签物体性估计**：

1. 前向跑网络，用 forward hook 取**最后一个卷积阶段**（layer4，stride=32）的特征图
2. 把 `fc` 的 1000 个类别权重当作 **1×1 卷积**，得到每类一张激活图
3. 上采样到输入分辨率，**对所有类别取最大值** → objectness map
4. 逐图归一化（99/1 百分位）+ 高斯平滑（σ=4）

**两个合法性性质**：
- 网络是 ImageNet 预训练，PACS 不在 ImageNet 中 → **无目标域信息泄漏**
- 地图**只用于生成增强图**；分类器从同一 ImageNet checkpoint 训练，**从不看这张地图**

**为什么不用真标签**：用标签会让增强变成**标签依赖操作**，而标签恰恰是分类器应该推断的东西。

**实测覆盖率**（`runs/line_art_preflight.json`）：

| 类别 | attention 覆盖 | spectral 覆盖 | sobel 覆盖 | 与 sobel 相关性 |
|---|---|---|---|---|
| dog | 28.8% | 0.42% | 42.2% | 0.26 |
| elephant | 26.8% | 0.92% | 39.2% | 0.05 |
| giraffe | 31.4% | 0.99% | 23.6% | 0.50 |
| guitar | 38.7% | 0.31% | 21.4% | 0.39 |
| horse | 34.5% | 0.45% | 39.4% | 0.18 |
| house | 43.2% | 0.24% | 40.2% | 0.44 |
| person | 34.8% | 0.75% | 30.2% | 0.12 |

**关键读数**：
- **注意力覆盖 ≈ 27–43%**，远高于 `spectral` 的 **0.24–0.99%**（这正是 `ours_fg` 幅度小的原因）
- 注意力与 Sobel 相关性仅 **0.05–0.50** → **两者语义确实不同**，是互补信号
- → **注意力门控具备可行性前提**

### 2.3 线稿绘制：注意力软门控（`line_attn`）

实现于 `repo/member3_structure_preserving/line_art.py` → `draw_line_art`。

```
labels  = SLIC 超像素分割(image)          # 决定"边界在哪"
region  = 每个超像素的注意力均值           # region_attention()
boundary= 像素邻接不同 label 的地方        # boundary_map()

对每个边界像素，取它四周四个邻居区域注意力:
    side = max(region[left], region[right], region[up], region[down])
    is_foreground = side >= foreground_threshold

强度分配:
    gate=True  →  前景边界: foreground_strength(满强度)
                  背景边界: background_strength × side   ← 随注意力淡出
    gate=False →  所有边界同一强度（对照基线）

线宽膨胀 (line_width) → 墨量 → PNG
```

**关键设计决策：墨色即强度**。

```python
ink    = 255.0 * (1.0 - drawing)      # 白纸上画线，线的暗度 = 强度
picture[mask] = ink                   # 灰度化到 RGB
```

**为什么**：若改用"压暗原图颜色"，墨色会同时依赖物体颜色和强度，而两个对照组是**按强度匹配**的 —— 两个量就不一致了，对照组匹配的是一个训练根本看不到的量。现在**保存的图片与强度图精确对应**，墨量可以从图片独立还原。

**保存格式**：**PNG，不是 JPEG**。线稿大部分是白纸 + 少量深色笔画，JPEG 的色度子采样和量化会改变笔画暗度 —— 而这正是两个对照组匹配的那个量。**无损往返是协议正确性的前提。**

### 2.4 软投票的具体实现（`line_attn_vote`）

实现于 `repo/member4_training_eval/build_line_art_sets.py` → `_soft_vote`。

**核心思想**：**每一条边界都画**，其暗度由**边界两侧区域的注意力加权平均**决定 —— 而不是二值切分。

```python
labels   = superpixel_labels(image, config)     # SLIC
region   = region_attention(labels, attention)  # 每超像素注意力均值
boundary = boundary_map(labels)

for each boundary pixel (ys, xs):
    here   = labels[ys, xs]
    across = 该像素另一侧邻居的 label
    other  = 垂直方向另一侧邻居的 label

    first  = region[here]
    second = region[across]

    # 软投票：两侧的加权平均，强的一侧权重稍大
    vote   = 0.5 * (first + second) + 0.25 * max(first, second)
    strength[ys, xs] = clip(vote, 0, 1)
```

**语义**：
- 两个**前景**区域之间的边界 → 暗（物体内部轮廓）
- 两个**背景**区域之间的边界 → 淡
- 前景/背景交界 → **连续过渡**，而非硬切

**与 `line_attn` 的本质区别**：`line_attn` 是 `max(side)` 式的硬二值门（前景满强度 / 背景 × side），`line_attn_vote` 是**双侧加权的连续投票**。

### 2.5 两级对照协议（方法学核心）

软投票的结论**完全依赖于对照组的正确性**。这里有**两个正交**的对照：

| 单位 | 匹配量 | 回答什么问题 |
|---|---|---|
| `line_plain_total` | **总墨量** | 门控是否只是"改变了墨量分布"？ |
| `line_plain_foreground` | **前景墨量** | 门控是否只是"在物体轮廓上画得更重"？ |

**匹配方式必须解两个权重，而不是整体缩放**：

```python
def solve_ink_weights(drawing, mask, foreground,
                      target_total=None, target_foreground=None):
    foreground_mass = drawing[mask & foreground].sum()
    background_mass = drawing[mask & ~foreground].sum()
    if target_total is not None:
        factor = target_total / (foreground_mass + background_mass)
        return factor, factor              # 两者同倍 → 总墨量守住，前景墨量变
    if target_foreground is not None:
        factor = target_foreground / foreground_mass
        return factor, 1.0                 # 只调前景权重 → 前景墨量守住
    return 1.0, 1.0
```

**为什么不能整体缩放**：整体缩放会**同时改变前景墨量**（副作用），那么两个对照就变成同一张图。**分别解前景/背景权重，才能让两个对照真正正交。**

**这三个 bug 已在 `repo/docs/incident_2026-11-24_lineart_controls.md` 中完整记录并修复**（`rescale_ink` 文档与实现不符、渲染丢弃解出的权重、两套墨量定义不一致）。

### 2.8 结论：硬门控无效，但软投票**部分成立**

必须把"注意力门控"和"软投票"分开评价 —— 它们的结论**相反**：

**① 硬门控（`line_attn`）无效 —— 但失败方式符合预期**

| 机制层 | 下游层 |
|---|---|
| 墨量前景占比 79.93% vs 对照 55.09%（**+24.8 点**） | **+0.18 点 (p=0.75)**，Cohen's d = 0.09 |
| 门控**确实**把墨移到了前景 | Sketch 域 **−0.35 点**（反而变差） |

→ **"机制有效" ≠ "下游有效"**。硬门控是一个**二值开关**（前景满强度 / 背景 × side），它把墨全堆到物体轮廓上，代价是**丢掉了背景的结构信息**。

**② 软投票（`line_attn_vote`）部分成立 —— 而且比门控好**

| 比较 | 差值 | p |
|---|---|---|
| 软投票 − 门控 | **+1.56 点** | **0.0370** |
| 软投票 − 总墨量对照 | **+1.73 点** | **0.0115** |
| 软投票 − 前景墨量对照 | **+1.54 点** | **0.0268** |

**关键：软投票的增益在 Sketch 域最大（+2.34 点）**，其次 Cartoon（+1.78），Art（+0.55）。

→ **可证伪预测成立**：增益**集中于 Sketch**（唯一保留形状、丢弃纹理的域）→ **形状偏置假说得到支持**（弱支持，单次实验）。

**③ 但整体仍然没有超过 `original`**

- 软投票 40.79% vs `original` 40.83% → **−0.04 点 (p=0.98)，完全打平**
- 三个线稿组（39.06 / 39.25 / 40.79%）**全部 ≤ `original`**

→ **线稿单独训练丢失了纹理/颜色/现实感信号，把基线信息全丢了**。软投票只是在"线稿这个错误的载体"上，把形状信息榨出了 +1.73 点。

**④ 最重要的推论：软投票的收益说明"形状信号有用"，但"线稿"这个载体错了**

软投票 vs 硬门控 **+1.56 点**的差距，完全来自**强度分配的连续性**（`0.5·(a+b) + 0.25·max(a,b)` vs 二值 max 门）。

> **这直接指向本文档第 3 节的核心主张**：把线稿换成**保留完整图像内容、只做局部连续调制**的形式（即 AdaIN 特征层的 α 图），应该能同时拿到形状信号和纹理信息 —— 而这正是 α=1.0 + 稀疏融合地图要解决的问题。

**⑤ 两条独立失败线，共同指向同一结论**

| 失败线 | 证据 |
|---|---|
| 硬门控（形状信号用**离散开关**传递） | 机制 +24.8 点，下游 +0.18 (p=0.75) |
| `center` 地图（形状信号用**连续但过强**的方式传递） | EdgeScore 最优，下游 −3.48 点 (p=0.0010) |

→ **形状信号需要"连续 + 温和"的传递方式**。软投票在离散端失败了，`center` 在连续端过猛失败了。**中间的某个强度也许才是对的 —— 这正是融合稀疏 α 图的设计目标。**

### 3.2 发现 1：α（样式强度）是唯一的主导变量，空间调制净效应 ≈ 0

混合公式：`alpha_map = α·(1 − β·M)`，特征混合 `F = alpha_map·AdaIN(Fc,Fs) + (1−alpha_map)·Fc`。β=0 时退化为常数 α（纯 AdaIN）。

| α | 均匀 AdaIN | 空间调制 `ours` | 差 | 匹配对照 `adain_matched` | **调制 − 对照** |
|---|---|---|---|---|---|
| 0.25 | 41.95% | 39.82% | −2.13 | 40.87% | −1.05 |
| 0.5 | 47.36% | 45.22% | −1.14 | 45.39% | −0.17 |
| 0.75 | 51.11% | 47.76% | −3.35 | 47.69% | **+0.07** |
| **1.0** | **54.23%** | 50.09% | −4.14 | 50.45% | −0.36 |

**读数**：
- **空间调制 vs 其严格匹配对照：−1.05 / −0.17 / +0.07 / −0.36 点 → 平均 ≈ −0.4 点，即"没有贡献"**
- 而 α 从 0.5 → 1.0 带来 **+6.87 点**

**β-sweep 印证**（α=0.5，β=0 即均匀）：

| β | `adain_matched` avgacc |
|---|---|
| 0.0 | **47.54%** |
| 0.3 | 46.93% |
| 0.5 | 45.96% |
| 1.0 | 44.40% |

**β 从 0 → 1.0 单调下降 3.14 点，而 α 从 0.5 → 1.0 上升 6.87 点。**

> **结论：全部地图搜索（Sobel / 光谱 / 中心 / 注意力门控 / 软投票）都在优化一个已被证明单调有害的参数。收益全在 α 上。**

### 3.7 关于"多方法融合做软投票"的正确形式

你的直觉方向是对的，但**之前的实现形式错了**。对比：

| | 之前的"软投票"（线稿） | 正确的融合形式 |
|---|---|---|
| 投票对象 | 边界**位置**的墨色 | **每个像素该保留多少内容** |
| 产出 | 线稿 vs 均匀线稿的二选一 | **一张 α 图** |
| 信号数量 | 2（注意力 + 色块） | N 个异质信号 |
| 失败原因 | 门控 +24.8 点墨量，下游 +0.18 (p=0.75) | — |

**正确形式**：

```
alpha_map(x,y) = 1 − β · M_fused(x,y)
M_fused = Σ_i w_i · M_i     (w_i 按信号可靠性预先固定，不看目标域)
```

**它与"选一个最好的 M"的本质区别**：它降低的是**单信号的噪声**，而不是在候选中挑更准的那个。

**为什么这能同时解决我们遇到的两个失败**：
- Sobel 失败：mean(M)=0.36 → 总强度被砍 25%
- `spectral` 失败：只有 0.24–0.99% 像素 > 0.5 → 覆盖太小

**融合 + 稀疏化同时解决这两点**：多信号取交集 → 既准又稀。

**而且它正好落在两条失败线之间**（见 2.8 ⑤）：

| 尝试 | 形状信号的传递方式 | 结果 |
|---|---|---|
| 硬门控线稿 | **离散开关**（二值 max） | +0.18 点 (p=0.75)，过猛/丢失背景结构 |
| `center` 地图 | **连续但强度过大**（deficit 0.193） | −3.48 点 (p=0.0010)，过猛 |
| **融合稀疏 α 图** | **连续 + 温和 + 精准** | 目标 |

**可测量的设计约束**（在训练前就能验证）：
1. `mean(M_fused) ≤ 0.15` → 总强度损失 ≤ 3 点（对照 `center` 的 deficit 0.193，`spectral` 的 0.038 但覆盖仅 0.3–1%）
2. 物体覆盖 ≥ 30% → 保护有效（对照 `spectral` 的 0.3–1%，注意力图已达 27–43%）

**候选信号**（全部 label-free）：
- **ImageNet ResNet-18 objectness**（已实现 `attention_map.py`，覆盖 27–43%）
- **DINOv2 自注意力**（最强无监督分割）
- 光谱显著度（已实现 `foreground_map.py`）
- 深度边缘（预训练深度模型）
- Sobel（作为对照项，应降权）

**成本**：15 分钟无 GPU 预检（算各信号的 mean(M) 和物体覆盖/召回）。**如果预检不达标，直接放弃该方向，省下后续全部训练成本。**

### 3.8 一个反直觉的洞察：PACS 上"更强样式"可能才是对的

**PACS 的域差异主要是艺术风格（Art / Cartoon / Sketch），不是纹理域（VLCS 那种）。**

**过度样式化恰恰是让模型学会风格不变特征的正确机制** —— 风格化得越狠，"这是素描笔触还是油画笔触"就越不可能成为可用的判别线索。

这与"少样式化保结构从而提升 DG"的直觉**方向相反**，而数据站在"更多样式"这边：
- α 越大越好（0.37 → 0.5 → 0.75 → 1.0 → 54.23%）
- β 越大越差（= 少施加样式 → 越差）

**具体可试的三个子方向**（都符合"融合多视图"的思路）：
1. **多风格池 + 强 α** —— subpool 实验只在 α=0.5 做过（43.20 / 43.67），在 α=1.0 下风格多样性可能才显现价值
2. **每个 epoch 换风格**（当前是固定配对）→ 这才是真正的"风格增强"
3. **风格强度随机化**（α ~ U(0.5, 1.0)）→ 强制模型忽略风格的绝对幅度

   - 只重跑关键 5 组（`original` / `duplicate` / `adain_matched` / `adain_a1p0_b0p7` / 新融合组）：**3.5 小时**，旧的留作"固定步数"协议的附录

   - 同时并行启动 **3.5 的协议修复重跑**

## 5. 一句话总结

> **今天的三条经验线指向同一个结论：**
>
> 1. **机制指标（EdgeScore）不能排序，只能排除** —— 安全门 + 机制排序选出了 `center`，下游 −3.48 点。
> 2. **机制有效 ≠ 下游有效；但"传递方式"比"信号本身"更重要** —— 硬门控机制 +24.8 点却下游 +0.18 (p=0.75)；把同一份注意力信号换成**连续加权**的软投票，立刻变成 +1.56 点 (p=0.037)，且增益**最大落在 Sketch（+2.34 点）** → 形状偏置假说弱支持。
> 3. **真正的主导变量是 α，而它一直被我们放在次要位置** —— 全组最优 54.23% 来自零机制的纯 α=1.0 AdaIN；且所有增强组因 epoch 减半而被系统性低估。
>
> **下一步：修 epoch → 在 α=1.0 体制下重做地图搜索 → 用多信号融合的稀疏 α 图替代"选一个最好的 M"。**
>
> **理由**：软投票已经证明"形状信号有用"（+1.73 点 vs 匹配对照），`center` 已经证明"连续调制有用但过猛"（EdgeScore 最优）。**缺的只是一个强度温和、位置精准、且不牺牲总强度的载体 —— 那就是融合稀疏 α 图。**
